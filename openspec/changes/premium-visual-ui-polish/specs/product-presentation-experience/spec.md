## ADDED Requirements

### Requirement: Product-first landing viewport
The web landing page SHALL present Liiiraa Booster as the first-viewport signal with the actual product UI, a direct performance value proposition, and clear download or waitlist action.

#### Scenario: First viewport product signal
- **WHEN** a visitor opens the landing page on desktop or mobile
- **THEN** the brand/product name, product UI preview, value proposition, primary CTA, and one trust/proof signal are visible without relying on decorative-only art

#### Scenario: No marketing-only hero
- **WHEN** the landing page loads
- **THEN** the first viewport does not use a generic gradient, abstract illustration, or text-only hero in place of product evidence

### Requirement: Clean section rhythm
The landing page SHALL use a small number of deliberate sections with strong spacing, visible separation, and minimal competing content per viewport.

#### Scenario: Section scan
- **WHEN** a visitor scrolls through the landing page
- **THEN** each section communicates one main idea such as one-click optimization, game support, benchmark proof, features, trust, FAQ, or download

#### Scenario: Mobile section fit
- **WHEN** the landing page is viewed on mobile
- **THEN** section headings, CTAs, screenshots, game cards, and proof tiles do not overlap, clip, or require horizontal scrolling

### Requirement: Honest benchmark and proof modules
The landing page SHALL present benchmark, game support, testimonial, and trust proof only when the data is real, sourced, or clearly labeled as demo/example content.

#### Scenario: Benchmark display
- **WHEN** a benchmark comparison is shown
- **THEN** the UI includes metric names, hardware or test context when available, and avoids unsupported absolute performance claims

#### Scenario: Demo proof labeling
- **WHEN** proof content is not based on real shipped data
- **THEN** the UI labels it as example, preview, or coming-soon content rather than presenting it as a verified user result

### Requirement: Supported optimization showcase
The landing page SHALL show the kinds of optimization Liiiraa Booster performs using separated visual modules rather than a dense generic feature grid.

#### Scenario: Optimization module showcase
- **WHEN** a visitor reaches the feature area
- **THEN** they can distinguish system, game, network, GPU, power, startup/services, benchmark, and rollback features as separate modules

#### Scenario: Feature CTA relation
- **WHEN** a feature module includes an action
- **THEN** the action leads to a relevant download, waitlist, detail, or screenshot context instead of a generic repeated CTA

### Requirement: Conversion CTA polish
The landing page SHALL use consistent, polished CTAs for download, waitlist, Discord/community, and product detail actions.

#### Scenario: CTA hierarchy
- **WHEN** multiple CTAs appear in one section
- **THEN** one action is primary and the remaining actions use secondary or text/icon styling with clear labels

#### Scenario: CTA feedback
- **WHEN** a visitor hovers, focuses, submits, or hits an invalid waitlist/download state
- **THEN** the CTA provides polished visual feedback and accessible status messaging
