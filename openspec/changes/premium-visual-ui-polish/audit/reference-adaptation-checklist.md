# Reference Adaptation Checklist

Date: 2026-05-03

Use this checklist during implementation and screenshot review. It permits
structure and polish inspiration while blocking copied assets, copied copy,
exact layouts, and unsupported claims.

## Permitted Adaptation

- [ ] Product-first first viewport: Liiiraa name, Liiiraa product UI, direct
  performance value, one primary CTA, one secondary CTA, and one trust/proof
  signal are visible.
- [ ] One-click path: safe recommended changes have one obvious apply action
  while review/customize/advanced actions remain secondary.
- [ ] Optimizer lanes: Game Mode, System, Network, GPU, Power,
  Startup/Services, Benchmarks, Rollback, and Settings are visually separable
  where applicable.
- [ ] Proof modules: benchmark deltas, supported games, rollback availability,
  backup state, signed update state, and confidence/source metadata use
  repeatable Liiiraa-native primitives.
- [ ] Section rhythm: landing sections each communicate one idea, with clean
  spacing and no dense all-purpose feature grid.
- [ ] Onboarding/install flow: download/waitlist, install, first run, scan,
  apply, benchmark, and rollback steps use plain verbs and visible progress.
- [ ] Safety framing: restore points, backups, blocked tweaks, reboot
  requirements, and rollback capability are visible before apply.

## Blocked Adaptation

- [ ] No Hone logos, marks, screenshots, videos, thumbnails, icons, app frames,
  avatar images, or proprietary assets are imported.
- [ ] No exact Hone phrases, CTA labels, section headlines, testimonials, FAQ
  wording, benchmark copy, or support copy are copied.
- [ ] No exact Hone layout measurements, card counts, image crops, animation
  timing, or visual identity patterns are reproduced.
- [ ] No Hone benchmark numbers, supported-game counts, user counts, customer
  claims, premium claims, or safety claims are reused.
- [ ] No external testimonials or social proof are shown unless sourced,
  licensed, and clearly attributable.
- [ ] No invented Liiiraa performance claims appear without real data or an
  explicit example/preview/coming-soon label.
- [ ] No account, payment, download, Discord/community, or affiliate flow is
  implied as live unless it is actually implemented.

## Screenshot Review Questions

- [ ] Does the desktop first screen have one dominant next action?
- [ ] Can a user distinguish scan, safe apply, game mode, benchmark, rollback,
  and trust without reading every paragraph?
- [ ] Are dense tweak details moved into ledgers, drawers, inspectors,
  expandable rows, or secondary sections?
- [ ] Are destructive, rollback, locked, loading, success, and disabled states
  visually distinct and accessible?
- [ ] Does the web first viewport show actual product evidence rather than
  decorative-only art?
- [ ] Do mobile screenshots avoid clipped labels, horizontal scrolling, CTA
  collisions, and oversized headings in compact sections?
- [ ] Are proof modules honest about source, hardware/context, confidence, and
  example status?

## Review Sign-Off

- [ ] Structure and UX lessons adapted.
- [ ] Liiiraa identity preserved.
- [ ] External assets and exact copy excluded.
- [ ] Unsupported claims excluded or labeled.
- [ ] Desktop screenshots reviewed.
- [ ] Web screenshots reviewed.
