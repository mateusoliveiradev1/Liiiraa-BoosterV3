## Hone Landing Patterns To Adapt

- Product-first promise: the first viewport combines a direct gaming performance
  value proposition, prominent download action, visible product UI, game proof,
  and social proof. Liiiraa should keep the same immediacy, but use Liiiraa
  screenshots, Liiiraa copy, and only verified or clearly labeled proof.
- One-click framing: the page repeatedly explains optimization as a simple
  starting action. Liiiraa should map this to a safe one-click path that stays
  rollback-backed and excludes high-risk or blocked tweaks.
- Game support proof: the landing uses supported-game cards and benchmark areas
  to make game coverage concrete. Liiiraa should show supported modules and
  games as separate, scan-friendly product evidence rather than a dense generic
  feature grid.
- Feature section rhythm: Hone separates one-click optimization, boost-up tools,
  game settings, system backup, pro settings, testimonials, FAQ, and final
  download intent. Liiiraa should preserve the section clarity while replacing
  identity, claims, visuals, and categories with native product concepts.
- Conversion repetition: download CTAs appear at key decision points. Liiiraa
  should provide one dominant CTA per section, with secondary waitlist/detail
  actions styled consistently and never competing with the primary action.

## Hone Install Flow Notes

- The get-started page embeds the YouTube video `YfZTPu9ZPRY`, titled "How To
  Install Hone! The BEST PC Optimizer!!!" in YouTube oEmbed metadata. The page
  around the video structures onboarding as download, account setup, game
  optimization, optimization tracking, and start gaming.
- The install support article breaks setup into account creation, download,
  installer launch, install location, terms acceptance, completion, open app,
  authentication, and apply optimizations.
- The install flow gives a useful reference for Liiiraa onboarding: fewer steps
  on screen at once, plain verbs, visible progress, and a clear post-install
  next action. Liiiraa should not copy the installer visuals, the video frames,
  the title style, or account-first assumptions unless account flows exist.

## Hone Game Mode And Optimization Flow Notes

- The usage support article positions the home page as a hub with shortcuts,
  live hardware/system sensors, and real-time performance monitoring.
- Hone's optimization page uses filters to separate optimization intent:
  FPS and latency, network and ping, quality of life, and privacy.
- The boost-up page separates temporary cleanup/refresh tools from persistent
  optimization settings.
- The backup page is treated as a first-class area and recommends restore
  points before optimization.
- The games page supports automatic game detection, a game list, and
  performance or optimal presets for supported games.
- The recommended optimizations article explicitly warns that FPS gains are not
  guaranteed, results vary by system, recommendations are not mandatory, and
  users should revert if instability appears.
- The game settings guidance frames supported game optimization as presets,
  visual setting changes, CPU/GPU usage tuning, background interference
  reduction, frame pacing, input latency, and a warning that game settings vary
  per title.

## Liiiraa Baseline Observations

- Desktop already has strong safety language, rollback state, trust state,
  benchmark proof, and route coverage. The polish issue is not absence of
  information; it is that many panels compete for attention in the same viewport.
- Web already uses a product-first first viewport, proof section, module
  sections, trust section, and waitlist route. It still reads more like an
  internal product concept than a finished landing page because the product
  visual is illustrative, the palette is one-note, and proof is example-heavy.

## Adaptation Guardrails

- Do adapt: product-first hierarchy, visible app preview, separated optimizer
  modules, game support proof, backup/trust prominence, FAQ/final CTA rhythm,
  one-click path clarity, and honest benchmark methodology.
- Do not adapt: Hone logo, screenshots, videos, exact copy, visual identity,
  exact layout measurements, testimonials, benchmark numbers, supported-game
  counts, premium plan claims, or download/account assumptions.
